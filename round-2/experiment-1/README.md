## Layman Summary

Tests whether an LLM's numeric answers become less consistent simply from repeating a math question back, or only when generic verification instructions are added on top.

## Full Summary

This experiment decomposes iteration-1's confounded 'relevant elaboration' prompt condition into two isolated conditions -- paraphrase_only (the GSM8K question restated redundantly, with zero verification-scaffolding language) and paraphrase_scaffold (the same restatement plus generic verification scaffolding such as unit-consistency reminders and step-by-step checks, padded to the same ~250-extra-token 'medium' length tier used by iteration-1's filler condition). Because the paired sibling dataset artifact that was supposed to supply these two conditions had not yet produced output at execution time, and iteration-1's own tier-2 'relevant' field was found to be corrupted (containing a literal unsubstituted '{question}' template placeholder and mid-sentence truncation), both conditions were constructed fresh in build_dataset.py from iteration-1's canonical (question, gold-answer) control rows, using the same scaffold-sentence pool iteration-1 documented for its 'relevant' condition. This fallback is logged explicitly in method_out.json['metadata']['deviations_from_plan'] and in each new row's metadata_self_constructed_fallback flag. The two new conditions were sampled alongside carried-forward bare-question control (length tier 0) and length-matched filler (tier 2) rows for the same 8 seed problems (first 8 GSM8K seed_ids sorted), giving 32 unique prompts total. Each prompt was sampled 15 times at temperature 0.7 across the identical 3 OpenAI-hosted OpenRouter models used in iteration-1 (openai/gpt-4o-mini, openai/gpt-4.1-mini, openai/gpt-4.1-nano), with logprobs and top-5 alternates enabled, for 1440 total API calls costing $0.33 (well under the $6.93 per-run hard budget derived from the shared $10 cap minus iteration-1's already-logged $2.07 spend minus a $1 safety margin). The answer-extraction regex cascade and both entropy proxies (mean Shannon entropy of the top-5 renormalized token distribution over the first 20 generated tokens, and at the located answer token) were ported verbatim from iteration-1's method.py so results are byte-comparable in schema and directly poolable with iteration-1's per-(prompt,model) aggregates. method.py implements a resumable append-only JSONL completion log keyed on (prompt_id, model, sample_idx) that was smoke-tested (verified skip-on-rerun with zero duplicate calls) before the full run. Outputs are aggregated to per-(prompt,model) cells with n_valid_samples, answer_mean/sd/variance/cv, frac_correct, and both mean entropy proxies, written to method_out.json (96 examples, one per prompt x model cell) validated against the aii-json exp_gen_sol_out schema (PASSED), with full/mini/preview variants generated. A dedicated 'decomposition_comparison' block in the metadata directly answers the research question: restatement_effect_cv (paraphrase_only minus filler, both tier 2) = +0.103, meaning pure redundant restatement raised mean answer CV relative to length-matched irrelevant filler; scaffolding_effect_cv (paraphrase_scaffold minus paraphrase_only) = -0.101, meaning adding generic verification scaffolding on top of the restatement did NOT further destabilize answers and in fact roughly offset the restatement effect -- suggesting the culprit behind iteration-1's confounded 'relevant elaboration' variance increase is redundant restatement itself, not the scaffolding language, though this reads on a self-constructed (not independently authored) decomposition of the conditions and should be flagged as such in any downstream evaluation. Raw completions (1440 rows) are kept in outputs/raw_completions.jsonl for re-analysis, and per-(prompt,model) aggregates in outputs/prompt_model_results.csv.
